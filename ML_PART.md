# ML-модуль: Decision Tree для определения приоритета задания

Роль: ML-разработчик. Модуль отвечает за обучение модели, её оценку и функцию предсказания, которую вызывает интерфейс Streamlit.

## 1. Задача и данные

- **Задача:** по четырём признакам задания определить его приоритет: `High`, `Medium` или `Low` (многоклассовая классификация).
- **Признаки:** `difficulty` (1–5), `days_left` (0–14), `estimated_hours` (1–8), `importance` (1–5).
- **Целевая переменная:** `priority`.
- **Датасет:** `student_task_prioritizer_dataset.csv`, 100 строк, пропусков нет. Классы: Low 41, Medium 38, High 21.
- **Происхождение данных:** синтетические данные, созданные командой для учебного проекта. Реальные персональные данные не используются. Способ создания и лицензию команда указывает в общем README.
- Категориальные признаки `subject` и `task_type` в модель не включены: проверка показала, что они не улучшают качество (см. п. 4).

## 2. Метод и обоснование

Выбрано **решающее дерево (`DecisionTreeClassifier`)**.

- Дерево даёт читаемые правила вида «если `days_left` ≤ 6,5, то …». Их можно показать на защите и объяснить пользователю.
- Масштабирование признаков не нужно, обучение быстрое, GPU не требуется.
- Работает на небольшой таблице из 100 строк.

**Сравнение с альтернативами** (повторная кросс-валидация 5×10 только на обучающей части):

| Метод | Accuracy (CV, среднее ± std) |
|---|---|
| Decision Tree (выбран) | 0,612 ± 0,088 |
| Logistic Regression | 0,818 ± 0,088 |
| k-NN (k=5) | 0,655 ± 0,086 |
| Random Forest | 0,668 ± 0,087 |

Логистическая регрессия в этом сравнении точнее дерева. Дерево выбрано ради интерпретируемости и потому, что в проекте модель задана как Decision Tree. Минус мелкого дерева: признаки, не попавшие в ветку, в решении не участвуют (см. разбор ошибки).

**Подбор параметров:** `max_depth` ∈ {2…6}, `min_samples_leaf` ∈ {1, 2, 3, 5}, 5-fold CV только на обучающей части. Лучший результат: `max_depth=3`, `min_samples_leaf=3` (при равных оценках взято более простое дерево).

## 3. Как запустить

Зависимости: `scikit-learn`, `pandas`, `joblib`, `matplotlib` (проверено на scikit-learn 1.9.1, pandas 3.0.6, matplotlib 3.11.2).

```bash
pip install scikit-learn pandas joblib matplotlib
python ml_model.py
```

Скрипт обучает модель, печатает отчёт, сохраняет `model.joblib` и папку `ml_outputs/` (метрики, матрица ошибок, правила дерева, примеры проверки). Фиксированный `random_state=42` делает результат воспроизводимым.

Использование в интерфейсе:

```python
from ml_model import predict_priority, predict_dataframe

predict_priority(difficulty=4, days_left=1, estimated_hours=6, importance=5)
# {'priority': 'High', 'probabilities': {'High': 1.0, 'Low': 0.0, 'Medium': 0.0}}

predict_dataframe(tasks_df)  # добавляет колонку predicted_priority
```

Если `model.joblib` отсутствует или не открывается (другая версия scikit-learn), модель переобучается автоматически. Некорректные значения (например, `difficulty=9`) вызывают `ValueError`.

## 4. Результаты проверки

Данные разделены в пропорции 80/20 со стратификацией: 80 строк на обучение, 20 на тест. Тестовая часть использована один раз, для итоговой оценки. Подбор параметров и сравнение методов делались только на обучающей части.

| Метрика | Значение |
|---|---|
| Accuracy на test | 0,70 (14 из 20) |
| Macro F1 на test | 0,673 |
| Базовый уровень (всегда «Low») | 0,40 |
| CV на train (5-fold, подбор параметров) | 0,70 |
| CV на train (повторная, 5×10) | 0,612 ± 0,088 |
| Признаки только числовые / + `subject`, `task_type` (CV) | 0,613 / 0,596 |

Матрица ошибок (строки: истина, столбцы: прогноз), файл `ml_outputs/confusion_matrix.png`:

| | High | Medium | Low |
|---|---|---|---|
| **High** | 2 | 2 | 0 |
| **Medium** | 1 | 5 | 2 |
| **Low** | 0 | 1 | 7 |

Полнота (recall): High 0,50, Medium 0,63, Low 0,88. Важность признаков: `days_left` 0,59, `importance` 0,21, `estimated_hours` 0,12, `difficulty` 0,09.

**Честная оценка качества:** на 20 тестовых строках одна строка весит 5 процентных пунктов, поэтому 0,70 ненадёжно. Повторная кросс-валидация даёт около 0,61. Реалистичный диапазон точности: 60–70 %, что заметно выше базового уровня 40 %.

### Три примера проверки (из тестовой выборки, `ml_outputs/validation_examples.csv`)

| Задание | difficulty | days_left | hours | importance | Истина | Прогноз | Уверенность |
|---|---|---|---|---|---|---|---|
| T073 | 3 | 1 | 5 | 5 | High | High | 1,00 |
| T078 | 1 | 14 | 2 | 3 | Low | Low | 1,00 |
| T017 | 4 | 2 | 7 | 1 | Medium | Medium | 0,71 |

### Разбор ошибки

Задание **T058** (`difficulty=5`, `days_left=3`, `hours=8`, `importance=5`): истинный приоритет High, модель дала Medium. В дереве все задания с `days_left` от 2 до 6 проходят через ветку «`difficulty` > 2,5 → Medium», и `importance` в ней вообще не используется. Для T058 важность максимальная, а в данных у High средняя важность 3,86. Похожая ошибка у T093 (`days_left=7`, `importance=5`): в её ветке важность проверяется только на уровне 1,5, поэтому значение 5 ничего не меняет.

### Ограничения

1. **Мало данных:** всего 100 строк, в тесте 20. Оценка нестабильна, а при другом разбиении цифры изменятся.
2. **Синтетические данные:** модель выучила закономерность этого набора, а не поведение реальных студентов. Правила неизвестной «разметки» могли быть другими.
3. **Мелкое дерево:** при глубине 3 часть признаков не участвует в решении, а в `tree_rules.txt` есть разбиения, которые приводят к одному и тому же классу (так работает sklearn, дерево не обрезается).
4. Классы упорядочены (Low < Medium < High), но дерево этого не учитывает: «ошибка на один уровень» и «ошибка на два уровня» для него равны.
